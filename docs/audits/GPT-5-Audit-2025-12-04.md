# Settlers of Lanc Codebase Audit (2025-12-04)
Prompt: Perform a thorough codebase audit and store it in a file in /docs/audits/[MODEL_NAME]-Audit-[TODAY's_DATE].md

Author: GPT-5  
Tracked Issue: SettlersOfLanc-2dm  
Scope: Repository-wide review of architecture, backend/frontend flows, typing, and tooling based on current code and project documentation.

## Approach
- Reviewed architectural guidance in `AGENTS.md` and `docs/system-architecture.md`.
- Inspected core code paths: `app/**` (pages, actions, API routes), `components/**`, `lib/services/**`, `lib/hooks/**`, `core/**`, `lib/repositories/**`, `lib/db/schema.ts`, `themes/**`.
- Checked configuration and tooling (`package.json`, `tsconfig.json`, `eslint.config.mjs`) and searched for automated tests via `rg --files -g "*test*.ts"`.

## High-Level Assessment
- Documented architecture (thin Server Actions -> services -> core -> repositories) is not enforced in code; significant business logic lives in actions and API routes with direct DB access.
- Authentication/authorization is absent in the live app despite Clerk being defined in the architecture, leaving mutations unauthenticated.
- No automated test coverage for complex game logic; risk of regressions is high.
- Supabase client initialization is brittle and will crash builds/renders without env vars.

## Findings

### High Severity
1) **Layering drift & business logic in actions**  
   - Evidence: `app/actions.ts` (~12k lines) performs room creation, game state mutations, and direct DB updates (e.g., debug progress card/resource/commodity grants) instead of 2-3 line delegates. `lib/services/lobby-service.ts` hits `db` directly, bypassing repositories. `components/board/Board.tsx` pulls `generatePorts` from legacy `engine/generatePorts.ts` rather than `core/engine`.  
   - Impact: Violates documented boundaries, duplicates logic, complicates testing and future refactors.  
   - Recommendation: Refactor actions to thin delegates into services; move DB access into repositories; migrate legacy utilities under `core/engine/**` and remove the top-level `engine/` folder.

2) **Missing authentication & authorization**  
   - Evidence: `app/layout.tsx` lacks Clerk provider/middleware; server actions and API routes accept arbitrary IDs with no user context; `clerkUserId` column in `lib/db/schema.ts` is unused; joining/playing only requires query params (`app/page.tsx`, `app/room/[id]/page.tsx`).  
   - Impact: Any user can impersonate others, mutate games, or read state across rooms; violates multi-tenant expectations.  
   - Recommendation: Wire Clerk provider and route protection, bind player records to authenticated users, and enforce authorization in every mutation (server actions/services) and query.

3) **Fragile Supabase client initialization**  
   - Evidence: `lib/supabase.ts` throws at import time when `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_ANON_KEY` are unset; hooks like `lib/hooks/useGameSubscription.ts` import it unconditionally.  
   - Impact: Local dev, linting, or tests fail without env vars; production misconfiguration causes runtime crashes.  
   - Recommendation: Lazily initialize the client, return a safe no-op when env vars are missing, and surface configuration errors via health checks instead of top-level throws.

4) **Mutation pathways diverge from documented Server Action-only plan**  
   - Evidence: Client flows still post to API routes for core mutations (`components/game/GameController.tsx` uses `/api/game/[roomId]/knight`, `/progress-card`, `/improvement`, etc.), while actions exist for overlapping concerns. API handlers contain business logic (e.g., `app/api/game/[roomId]/knight/route.ts`).  
   - Impact: Logic duplication, inconsistent validation, unclear cache/invalidations, and harder auditing of side effects.  
   - Recommendation: Consolidate mutations into server actions that call services; convert API routes to read-only or remove; ensure a single orchestration path per operation.

5) **Resource/terrain type conflicts and duplication**  
   - Evidence: `lib/types/game.ts` imports `ResourceType` from both `lib/board-data` and `core/engine/board/board-generator`; `core/rules/board-constants.ts` defines another `ResourceType`/`TerrainType` pair. Desert is still treated as a resource in some definitions (known issue).  
   - Impact: Type mismatches, potential runtime errors, and incorrect resource handling across ~20 files.  
   - Recommendation: Complete the planned split (`ResourceType` vs `TileType`), remove duplicate exports, and update all imports to a single source of truth.

6) **Zero automated tests for critical logic**  
   - Evidence: No `*.test.ts*` files found; only `npm run lint` exists.  
   - Impact: High regression risk for rules, validators, services, and API routes; bugs in progress cards/knight flows are hard to catch.  
   - Recommendation: Add unit tests for pure rules/validators (core), integration tests for services (with mocked repositories), and API/Server Action contract tests; wire CI to run lint+tests.

### Medium Severity
7) **Mis-typed route params/search params**  
   - Evidence: `app/board/flat/page.tsx` and `app/room/[id]/page.tsx` type `params`/`searchParams` as `Promise<...>` and `await` them.  
   - Impact: Breaks Next.js typing and static analysis, obscures required params, and risks runtime issues.  
   - Recommendation: Use `{ params: { ... }, searchParams: { ... } }` signatures, validate presence, and `redirect`/`notFound` as needed.

8) **Documentation and package metadata drift**  
  - Evidence: `docs/system-architecture.md` claims enforced 5-layer stack, Clerk, TanStack Query, and Next.js 15; codebase runs Next.js 16 without Clerk or TanStack. `README.md` is the default scaffold; `package.json` now reflects the updated app name `settlers`.  
   - Impact: Onboarding confusion and misaligned expectations for contributors.  
   - Recommendation: Either align code to the documented architecture or update docs/metadata to match reality; rename the package/app and provide an accurate README.

9) **Realtime/polling inconsistency and env coupling**  
   - Evidence: Lobby relies on 2s polling with ETags (`components/lobby-view.tsx`) while in-game uses Supabase realtime, both gated by the crashing Supabase client. API route signatures also misuse `params: Promise`.  
   - Impact: Mixed transport patterns, unnecessary load, and brittle behavior when env vars are absent.  
   - Recommendation: Standardize on a single transport strategy (realtime-first or resilient polling) with graceful fallbacks and correct route typing.

10) **Legacy engine utility outside modular boundary**  
    - Evidence: `components/board/Board.tsx` imports `generatePorts` from `engine/generatePorts.ts` instead of `core/engine/board/port-generator`.  
    - Impact: Violates the stated module boundaries and complicates future refactors.  
    - Recommendation: Relocate the utility into `core/engine/board` and update imports; remove the stray `engine/` directory.

### Low Severity / Observations
- Room code generation (`app/actions.ts`) does not check for collisions; extremely low probability but possible.  
- DB schema (`lib/db/schema.ts`) stores full game state as JSON without optimistic locking/versioning; consider row-level revisioning for concurrent mutations.  
- No rate limiting or request throttling on server actions/API routes.  
- Ensure `.env.local` (present locally) never contains committed secrets even though `.gitignore` excludes it.

## Recommendations & Next Steps
- Prioritize refactoring to enforce the documented layering (actions -> services -> core -> repositories) and remove business logic from actions/API routes.  
- Implement authentication/authorization with Clerk across UI, actions, and services, binding player/game access to authenticated users.  
- Harden environment handling (Supabase client) and standardize mutation/fetch pathways.  
- Launch a testing initiative covering rules/validators/services and key UI flows.  
- Reconcile documentation with the actual stack, and fix route typing issues to restore Next.js best practices.  
- Plan the ResourceType/TileType split and update imports to eliminate type drift.
